# Система обслуживания заявок на поступление на военную кафедру

Учебный прототип для лабораторной работы № 7. Версия **1.0.0** (см. `CHANGELOG.md`).
Стек: Python 3.10+, Streamlit, SQLite.

> Не загружайте в систему реальные документы и персональные данные. Для проверок есть папка `testdata/`.

### Что имитируется (в отчёте это нужно назвать прямо)

- Университетский единый вход заменён логином и паролем (учётные записи ниже).
- Почта не отправляется наружу: письмо записывается в журнал, у ИТ-службы есть переключатель «недоступна».
- Справочник «Студенты» (4 поля) и справочник «Специальности» заполнены тестовыми данными.
- Не реализовано: интеграция с 1С, SMS, лист ожидания, правило повторной подачи после отказа
  (в версии 1.0 после отказа повторная подача запрещена с пояснением).

## Запуск локально

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
streamlit run app.py
```

База создаётся при первом запуске в `data/app.db`. Сброс к исходным данным: кнопка у `it_service` или удаление файла.

## Развёртывание на Streamlit Community Cloud

1. Создайте репозиторий на GitHub и загрузите в него содержимое этой папки (папка `data/` в `.gitignore`).
2. Откройте https://share.streamlit.io и войдите через GitHub.
3. Create app → выберите репозиторий и ветку, в поле Main file path укажите `app.py`.
4. В Advanced settings выберите Python 3.11 или новее, нажмите Deploy.
5. Ссылку на приложение передайте тестировщику.

Важно: файловая система Community Cloud временная. Когда приложение перезапускается или засыпает, база
возвращается к исходным данным. Не рассчитывайте, что заявки сохранятся надолго: перед проверкой убедитесь,
что приложение не перезапускалось, а результаты сразу фиксируйте снимками. Для долгой проверки используйте
локальный запуск.

## Подготовка проверки

Тестовые файлы в `testdata/`:

| Файл | Для чего |
|---|---|
| `valid_document.pdf`, `valid_scan.png`, `valid_scan.jpg` | допустимые документы |
| `size_exactly_5MB.pdf` | граница: ровно 5 МБ — должен приниматься |
| `size_5MB_plus_1byte.pdf` | граница: на байт больше — должен отклоняться |
| `fake_text_renamed.pdf`, `png_content_in_pdf_name.pdf` | содержимое не соответствует формату |
| `empty.pdf` | пустой файл |
| `wrong_format.exe` | недопустимый формат (окно выбора файла может не показать его из-за фильтра) |

Быстрая подготовка данных: войдите как `it_service` и нажмите «Создать демо-заявки» — появятся 6 заявок
студентов 05–10. Для проверки превышения мест принять все шесть и сформировать список: на первой
специальности 3 заявки при 2 местах.

Что можно проверить по ролям:

- **Студент:** подача заявки, обязательные документы, формат и размер файлов, повторная отправка,
  просмотр статуса и писем, догрузка при «на доработке», доступ только к своей заявке.
- **Оператор:** очередь и фильтр, смена статуса, обязательность комментария для «отклонена» и списка
  документов для «на доработке», журнал статусов, повторное сохранение того же статуса.
- **Начальник учебной части:** сводка за период, пустой и неверный период, задержки.
- **Начальник военной кафедры:** закрытие приёма, условия формирования списка, число мест, превышение,
  блокировка статуса, снятие блокировки, выгрузка CSV.
- **ИТ-служба:** сбой почты, пометка «письмо не ушло», повторная отправка, задержка письма (≤ 5 минут).

## Автотесты

```bash
pip install -r requirements-dev.txt
python -m pytest tests -q
```

`tests/test_core.py` проверяет правила работы (32 проверки), `tests/test_ui.py` — вход и страницы ролей
(10 проверок). Автотесты проверяют только то, что было предусмотрено при разработке; ручная проверка
независимым тестировщиком нужна дополнительно.
